# ADR-002: Responsibility boundary between Toudocu and the agent


Toudocu performs reproducible operations. A person or agent interprets the
request and judges whether the result is correct.

<!-- toudocu:section context -->
## Context

Work often starts with a natural-language request, but the project model must
remain verifiable without an AI model or network access. If the CLI invents
relationships, requirements, or statuses, the documentation can no longer be
trusted to describe the project.

<!-- toudocu:section decision -->
## Decision

Toudocu performs deterministic operations: exact word and identifier search,
ID allocation, neutral scaffolding, structural readiness checks, context
collection, and—only after separate authorization—declared verification
commands.

The person or agent interprets the request, chooses related entities, writes
requirements and acceptance criteria, changes statuses, and marks `[x]` only
after obtaining real evidence. The CLI does none of this automatically.

<!-- toudocu:section consequences -->
## Consequences

- CLI results are reproducible and do not depend on an AI model.
- Scaffolds do not invent relationships or business rules.
- `task ready` remains read-only.
- `task candidates` lists current task candidates and waiting reasons but does
  not choose the next task.
- A person or agent must still review semantic accuracy.
- Natural-language orchestration is outside the public Go CLI contract.
