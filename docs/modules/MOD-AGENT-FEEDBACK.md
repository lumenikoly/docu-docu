# MOD-AGENT-FEEDBACK: Локальные запросы к агенту разработки

Модуль связывает сообщения человека с конкретным местом документации и
доставляет их внешнему агенту разработки через локальную очередь. Toudocu не
вызывает языковую модель и не зависит от Codex, Claude Code, OpenCode или
другого поставщика.

## Назначение

Читатель создаёт вопрос или запрос на изменение на странице документа либо в
разделе «Изменения». Сохранение сразу создаёт ожидающую запись очереди, а
сообщение остаётся редактируемым, пока агент не получил его через командную
строку. Агент проверяет актуальный документ и при необходимости код, затем
возвращает структурированный ответ в то же обсуждение.

## Границы

Портал создаёт цель `document` только для канонического Markdown. Changes также
создаёт цель `file` для обычного файла текущего рабочего diff. Диапазон доступен
только для UTF-8 текста до 2 МиБ; двоичный, большой или удалённый файл получает
цель целиком. `change_request` разрешает изменить `target.path` и однозначно
названные человеком дополнительные пути: для `document` — только в
канонической документации, для `file` — в безопасных путях репозитория. API
обратной связи не принимает исправления и сам не записывает файлы.

Состояние находится в пользовательском каталоге ОС, привязанном к каноническому
корню репозитория. Оно не попадает в Git и доступно CLI без запущенного
`serve`. Статический портал и каталоги переводов остаются только для чтения.

Portal загружает интерфейс обсуждений только после первого открытия панели или
действия над выделенным текстом. React-компоненты хранят лишь состояние
отображения; после конфликтов revision они повторно читают сервер и не создают
второй источник истины для обсуждений или доставок.

## Бизнес-правила

### BR-AGENT-FEEDBACK-001: Содержание не зависит от транспорта

`Discussion`, сообщения, `DocumentAnchor` и ответы хранят содержание разговора.
`AgentDelivery` хранит только сведения о доставке. Поэтому новый способ доставки можно
добавить без изменения истории обсуждения.

### BR-AGENT-FEEDBACK-002: Вопрос не разрешает изменение

Для `intent=question` агент отвечает, но не изменяет файлы. Только
`intent=change_request` разрешает проверить запрос и изменить `target.path`, а
также однозначно названные пользователем дополнительные пути в границах вида
цели. Утверждение пользователя не считается доказанным в обоих случаях.

### BR-AGENT-FEEDBACK-003: Ожидающее сообщение редактируемо

Сохранение атомарно переводит сообщение в состояние `submitted` и создаёт одну
ожидающую запись `AgentDelivery`. Пока запись имеет состояние `pending`,
сообщение можно изменить или удалить. После получения агентом сообщение
неизменяемо; уточнение является новым сообщением того же обсуждения.

### BR-AGENT-FEEDBACK-004: Очередь обрабатывается строго по порядку

`agent next` выдаёт только старейшую незавершённую запись. Пока она не
получила ответ, следующая запись не выдаётся. После истечения срока блокировки
агент повторно получает ту же старейшую запись. Повторный идентичный ответ
успешен, а другой ответ для завершённой записи отклоняется как конфликт. После
ответа доставка имеет состояние `responded` и больше не выдаётся, даже если
обсуждение осталось открытым. Новую доставку создаёт новое сообщение человека.

### BR-AGENT-FEEDBACK-005: Обсуждением управляет человек

Ответ агента не закрывает обсуждение. Пользователь может закрыть, открыть снова
или удалить любое обсуждение. Закрытые ветки показываются после открытых.

<!-- toudocu:section invariants -->
## Инварианты

- Сохранённое сообщение сразу видно в очереди.
- Сообщение редактируется только до атомарного получения агентом.
- Вопрос не даёт разрешения менять документацию.
- Каждая полученная доставка завершается ответом до получения следующей.
- Обработка запроса не запускает команды проверки и не расширяет изменение на
  не названные человеком связанные файлы.
- API обратной связи не записывает файлы репозитория и не запускает агента.
- Открытое обсуждение и незавершённая запись очереди не удаляются автоматически.

## Будущее расширение

Интерактивная проверка человеком добавит отдельный `ReviewGate`, который сможет
передать существующую `AgentDelivery` ожидающему агенту. Блокирующее ожидание,
подтверждение и решение проверяющего в текущую версию не входят.
