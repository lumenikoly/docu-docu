# Статический портал

Модуль превращает проверенную модель проекта в готовый портал: HTML-страницы,
навигацию, поиск, JSON-данные и машинный отчёт `report.json`. Результат команды
`build` можно разместить на обычном HTTP(S)-сервере. Команда `serve` использует
тот же портал, но добавляет локальные инструменты для чтения и изменения
исходных файлов.

<!-- toudocu:section code-location -->
## Расположение в коде

- сборка страниц и отчёта: `internal/app/site.go`,
  `internal/app/report_types.go`;
- шаблоны, встроенные ресурсы и данные для запуска интерфейса:
  `internal/site/`;
- исходный код и сборка браузерной части: `web/src/`, `web/vite.config.mjs`,
  `web/package-assets.mjs`;
- сгенерированные браузерные ресурсы: `internal/site/assets/generated/`;
- страницы процессов и пользовательских сценариев:
  `internal/app/process_site.go`;
- каталог экранов и карта переходов: `internal/app/screen_site.go`;
- локальный HTTP-сервер и документация API: `internal/app/server.go`,
  `internal/app/api_docs.go`;
- редактор, безопасная запись файлов и замена файла средствами ОС:
  `internal/app/editor_*.go`;
- общая оболочка разделов «Редактор» и «Изменения»:
  `internal/site/workspace.go`;
- темы и оформление проекта: `internal/app/site_config.go`.

<!-- toudocu:section boundaries -->
## Границы

Модуль не читает Markdown напрямую и не проверяет заново правила
документации. Он получает готовую проектную модель от
[MOD-MODEL](model.md) и строит из неё страницы. Изменять исходные файлы можно
только через локальный `serve`; статический портал остаётся доступным только
для чтения.

<!-- toudocu:section business-rules -->
## Бизнес-правила

### BR-SITE-001: Очистка выходного каталога не затрагивает защищённые пути

Перед `build --clean` Toudocu раскрывает символические ссылки и проверяет
итоговый путь. Нельзя очистить корень файловой системы, каталог исходной
документации, его родительский каталог или переданный напрямую символический
путь. Эти ограничения защищают файлы проекта от ошибочного значения
`--output`.

### BR-SITE-002: Портал работает на обычном статическом HTTP-хостинге

Результату `build` не нужны запущенный Toudocu, база данных, Node.js, CDN или
другие сетевые службы. Все нужные HTML-, CSS-, JavaScript- и JSON-файлы лежат
в выходном каталоге и используют относительные адреса. Поэтому портал можно
разместить как в корне сайта, так и во вложенном URL-пути.

Поддерживается открытие по HTTP(S). Работа через `file://` не поддерживается:
браузеры ограничивают загрузку локальных ресурсов, от которых зависят поиск и
часть интерактивных страниц. Для локального чтения используется `serve`.

### BR-SITE-003: Локальный сервер открывает файлы только через явные интерфейсы

Обычные маршруты `serve` раздают только собранный портал, а не произвольные
пути файловой системы. API редактора работает лишь с обычными файлами `.md`,
`.yaml`, `.yml` и `.json` внутри корня документации и отклоняет скрытые,
исключённые, выходные и проходящие через символические ссылки пути.

Changes является отдельным явным интерфейсом канонического `serve`: он может
читать отслеживаемые и новые неигнорируемые файлы внутри текущего репозитория,
чтобы показать diff, полный UTF-8-текст и обсуждения. Он проверяет путь, тип и
размер, не публикует абсолютные пути и не превращает сервер в общий файловый
обозреватель. По умолчанию сервер слушает loopback; `--host 0.0.0.0` явно
включает доступных клиентов локальной сети в границу доверия.

По умолчанию сервер слушает только loopback-адрес, то есть доступен с того же
компьютера. При запуске с `--host 0.0.0.0` пользователь сам открывает его
другим устройствам в локальной сети и должен считать их доверенными.

### BR-SITE-004: Mermaid работает автономно и в строгом режиме

Закреплённая версия Mermaid Tiny встроена в исполняемый файл. Браузер загружает
её, только когда диаграмма приближается к видимой области, и запускает с
`securityLevel: strict`. Внешний CDN не используется. Если синтаксис диаграммы
ошибочен, остальная страница продолжает работать, а рядом остаются сообщение
об ошибке и исходный текст диаграммы.

### BR-SITE-005: Карта экранов работает автономно

Карта строится из документов `SC-*` и связанных с ними переходов `TR-*`.
Фильтры, масштабирование, перемещение карты, боковая панель и пошаговое
проигрывание сценария работают на встроенных CSS и JavaScript, без сервера и
CDN.

В портале эти сущности разделены по назначению:

- «Пользовательские сценарии» содержит документы `UC-*`;
- «Процессы» содержит документы `FLOW-*` и открывается по адресу
  `processes/index.html`;
- «Экраны» содержит документы `SC-*`;
- общая карта экранов доступна отдельным пунктом, если её генерация включена.

Страница пользовательского сценария объединяет его описание, карту, шаги и
связи. Карточка экрана показывает число входящих и исходящих переходов. Типы
переходов различаются линиями, а интерактивные области экрана видны при
наведении мышью и при фокусе с клавиатуры.

Порядок основных разделов задан встроенным реестром, а не случайным порядком
обхода Go map. Их отображаемые названия берутся из `project.sections`;
встроенный раздел `flows` публикуется под именем `processes`, а `drafts`
находится после рабочих задач и перед руководствами. Каталог `drafts/index.html`
строится из свободных Markdown-файлов и не требует исходного `index.md`.

### BR-SITE-006: Темы не расширяют доверенную поверхность

Доступны только встроенные темы `classic`, `paper` и `terminal`, а также
системная, светлая и тёмная цветовые схемы. Их стили, стандартная иконка и
остальные ресурсы входят в исполняемый файл. Произвольные CSS, шрифты и плагины
тем не загружаются.

Логотип, иконка и изображение первого экрана могут браться только из обычных
файлов в `.toudocu/assets/`. При сборке они проходят те же проверки путей и
копируются в `assets/branding/`. Сетевой доступ для этого не нужен.

### BR-SITE-007: build и serve имеют разные возможности

`build` создаёт портал только для чтения. В нём нет редактора, раздела
«Изменения», Swagger UI, CodeMirror, наблюдения за файлами и кода локальной
пересборки. Найденные OpenAPI-описания копируются как обычные файлы портала.

`serve` поверх того же результата добавляет редактор, Changes, локальные
обсуждения, документацию API, наблюдение за исходниками и ручную пересборку.
Эти возможности относятся только к канонической документации, если сервер
запущен из её корня.

### BR-SITE-008: Запись защищена проверкой версии файла

При чтении файла редактор получает SHA-256-хеш его содержимого. При сохранении
сервер сравнивает этот хеш с текущим файлом. Если файл успел изменить другой
процесс, сервер возвращает конфликт и не затирает ни одну версию.

Обычная запись проходит через временный файл в том же каталоге: Toudocu
сохраняет права доступа, записывает и синхронизирует данные, затем атомарно
заменяет исходник. Для принудительной перезаписи нужны свежий хеш и явное
`confirmOverwrite`. Если исходник удалён, несохранённый текст можно скачать.
Диагностические предупреждения не запрещают сохранение.

### BR-SITE-009: Переводы изолированы от канонической рабочей области

Если `serve` запущен из канонического корня, настроенные переводы доступны
только для чтения по адресам `/_toudocu/locales/<locale>/`. Переключатель
языка ведёт на документ с тем же относительным путём, если он существует; для
сгенерированной страницы используется совпадающий выходной путь, а при
отсутствии соответствия — главная страница выбранного языка.

Переведённый портал не получает редактор, раздел «Изменения», API записи,
кнопки пересборки или пути к исходникам канонической документации. Если
`build` или `serve` запустить непосредственно на корне перевода, результат
тоже остаётся одноязычным и доступным только для чтения.

### BR-SITE-010: Мягкая навигация доступна только в каноническом serve

Только канонический портал, открытый через `serve`, может менять содержимое
между внутренними HTML-страницами без полной загрузки. После наведения мышью
или фокуса с клавиатуры он заранее загружает не более восьми последних
страниц. Перед заменой проверяется текущая версия рабочего пространства.

Кнопки браузера «Назад» и «Вперёд», якорные ссылки, положение прокрутки и
перенос фокуса к основному содержимому сохраняют обычное поведение. Переходы в
редактор, «Изменения», документацию API, перевод или на внешний сайт всегда
загружают страницу целиком. То же происходит при сетевой ошибке, неожиданном
HTML или новой версии рабочего пространства.

Поисковый индекс загружается при первом поиске и остаётся в памяти до полной
перезагрузки. Mermaid загружается только при появлении первой близкой
диаграммы.

### BR-SITE-011: Документация API автономна и ограничивает запись

Страница `/_toudocu/api-docs/` существует только в каноническом `serve`. Она
использует встроенный Swagger UI 5.32.12 и OpenAPI-файлы с того же сервера;
CDN и внешние запросы запрещены политикой CSP. В интерфейсе можно выполнить
только безопасные запросы `GET` и `HEAD`.

В статической сборке, переводах и `serve`, запущенном непосредственно из корня
перевода, этой страницы и её ресурсов нет.

### BR-SITE-012: Рабочие поверхности используют единое оформление

Портал, «Редактор» и «Изменения» хранят выбранные тему и цветовую схему под
одними ключами `localStorage`. Скрипт `appearance.js` применяет тему,
системную/светлую/тёмную схему, акцентный цвет, плотность и ширину содержимого
до загрузки основных стилей. При изменении он отправляет событие
`toudocu:themechange`.

«Редактор» и «Изменения» используют общую шапку с названием проекта,
переходами между тремя разделами и обозначением текущей страницы через
`aria-current`. Контекстные действия остаются в собственной панели каждого
раздела. Смена темы не пересоздаёт состояние CodeMirror и не сбрасывает
открытый отчёт об изменениях.

Общие компоненты Portal, «Редактора» и «Изменений» используют семантические
переменные `--td-*`. Темы `classic`, `paper`, `terminal`, цветовые схемы
`system`, `light`, `dark` и плотность `comfortable`, `compact` изменяют эти
переменные, а не отдельные палитры возможностей. Роли шрифтов body, interface,
heading и mono сохраняются во всех рабочих поверхностях. Новые общие
компоненты получают контуры Lucide из локального реестра с единой толщиной
линии; декоративная SVG-иконка скрыта от дерева доступности, а самостоятельная
значимая иконка получает доступную подпись. Прежние иконки остаются допустимы
до постепенного переноса.

### BR-SITE-013: Go явно задаёт возможности браузерной части

Каждая страница получает встроенный JSON-блок запуска. В нём есть версия
схемы, вид окружения, ссылка на текущую страницу, относительные пути к ресурсам
и список доступных возможностей. Для статической сборки `editor`, `changes`,
`rebuild` и `taskWorkspace` всегда выключены. Адреса локальных API появляются
только в `serve` и остаются в пределах того же origin.

Браузерный код пропускает неизвестные поля для обратной совместимости, но
показывает понятную ошибку, если блока запуска нет или версия его схемы не
поддерживается.

### BR-SITE-014: Дорожная карта изменяется только ограниченной операцией

В каноническом `serve` на странице `roadmap.md` можно добавить только один
новый незавершённый пункт `DLV-*` в уже существующий раздел второго уровня.
Сервер возвращает список допустимых этапов, проверяет идентификатор и текст,
сравнивает хеш файла и точечно вставляет строку, сохраняя исходный вид
переносов. Браузер не разбирает Markdown и не решает, допустима ли запись.

В статическом портале и переводах дорожная карта доступна только для чтения.

### BR-SITE-015: Проверка версии не влияет на доступность портала

Проверка обновления включена только в каноническом `serve`. При первом
обращении сервер один раз запрашивает метаданные последнего стабильного релиза
из фиксированного GitHub API, ограничивает время и размер ответа и хранит
результат до завершения процесса. Если версия новее, портал ненавязчиво
предлагает открыть официальный релиз. Скрытие уведомления действует только для
этой версии.

Любая ошибка проверки остаётся незаметной и не мешает работе портала. Флаг
`--no-update-check` полностью отключает эту возможность. Она также недоступна
в `build`, переводах и `serve`, запущенном из корня перевода.

### BR-SITE-016: Родительская задача показывает актуальное поддерево

Страница `TASK-*` с детьми показывает текущую задачу и всех её потомков как
вложенное дерево. Каждый узел содержит ссылку и текстовый статус из общей
проектной модели; статический портал и `serve` строят одинаковое представление.
Страница вложенного родителя ограничивается его поддеревом, а предки остаются в
навигационной цепочке. Исходный Markdown не хранит вычисленный список детей.

### BR-SITE-017: Боковая навигация показывает иерархию рабочих задач

В разделе рабочих задач боковая навигация показывает корневые `TASK-*` и
`BUG-*`. Потомки `TASK-*` вложены под родительскую задачу и могут сворачиваться
отдельно; открытая страница и её предки остаются раскрытыми. Выбранное состояние
сворачивания хранится локально и одинаково работает в статическом портале и
`serve`.

### BR-SITE-018: Work items получают специализированное рабочее представление

`work/index.html` использует Task Workspace, а не общий каталог документов.
Go заранее готовит derived state, readiness, зависимости, связи `parentTask` и
прогресс acceptance criteria; browser только фильтрует, группирует и меняет
Board, List и Tree. Статический HTML уже содержит Board и ссылки на задачи.
Workspace не содержит API для изменения статуса, запуска команд или drag-and-drop.

### BR-SITE-019: React ограничен прикладными поверхностями

Целевая UI-система разрешает отдельные React application roots для Editor и
Changes и управляемые `IslandHost` islands в каноническом `serve`. Обычные
страницы Portal, `appearance.ts`, `portal.ts` и `serve.ts` не зависят от React.
Новый island допустим без отдельного ADR, если получает возможности из
`PageBootstrap v1`, монтируется динамически, соблюдает общий lifecycle и не
владеет маршрутизацией или проектной моделью.

Editor и Changes получают Go-generated shell и владеют только DOM внутри своего
root. CodeMirror и CodeMirror Merge сохраняют собственное состояние документа,
selection, viewport, transactions и diff; React не зеркалирует это состояние.

### BR-SITE-020: Island изолирует lifecycle и отказ

В целевой UI-системе `IslandHost.discover()` идемпотентен, а один island instance имеет не более
одного React root. Перед заменой `.site-layout` soft navigation вызывает
`unmountAll()` только после полной проверки целевой страницы. Новая
`toudocu:pagechange` отправляется после замены `PageBootstrap` и синхронизации
ресурсов.

Ошибка загрузки, feature JSON или первого render переводит только конкретный
instance в `data-td-island-state="error"`. Go-generated содержимое, другие
islands и навигация продолжают работать. Activated island можно повторно
запустить новым действием; eager island повторяет попытку после следующего
перехода страницы.

### BR-SITE-021: Feature JSON не принимает решений за bootstrap

В целевой UI-системе Go безопасно сериализует feature-specific immutable view model в
`application/json`. Mount point может ссылаться на этот блок, но не хранит
permissions, capabilities, endpoints, runtime, locale, theme или абсолютные
пути. Эти данные поступают только из `PageBootstrap v1`. Feature проверяет свою
минимальную форму данных и локально обрабатывает ошибку.

### BR-SITE-022: Base UI дополняет native HTML

В целевой UI-системе native HTML остаётся базовым primitive. Base UI применяется только для
составного поведения, которое браузерный элемент не обеспечивает сам: dialog,
menu, context menu, popover, tooltip, select, combobox или сложные tabs. Обычные
кнопки, ссылки, подписи, панели, заголовки, badges и статические таблицы не
получают обязательную Base UI-обёртку.

## Инварианты

- `index.md` становится главной страницей, а не второй копией документа. На
  ней показаны сведения о проекте, текущий фокус, не более пяти рекомендуемых
  входных точек и содержательная часть исходного `index.md` без повторного H1 и
  служебных полей.
- Краткое текущее состояние появляется, только если есть `status.md`,
  `roadmap.md`, рабочие задачи или риски. Переход выбирается в порядке
  `status.md` → ближайший результат → каталог работ → риски.
- На страницах исходных Markdown-документов можно скопировать название и
  безопасный относительный путь. В каноническом `serve` рядом доступны
  переходы в редактор и просмотр изменений.
- Навигация показывает распознанный статус не только цветом, но и текстом. Для
  `TASK-*` и `BUG-*` дополнительно различаются незавершённый `☐` и завершённый
  `☑`.
- Текущая группа навигации раскрыта; выбор пользователя сохраняется локально.
  Главная страница не дублирует полные каталоги, дорожную карту, риски и задачи.
- Вложенная задача в боковой навигации не дублируется среди корневых задач;
  раскрытие её подзадач доступно с клавиатуры и не зависит только от цвета.
- Печатная версия сохраняет весь содержательный текст `index.md`.
- Каталоги, карта экранов, трассировка и страница состояния не притворяются
  обычными исходными документами и не показывают выдуманный путь к файлу.
- В статической сборке нет маршрутов, действий и ресурсов, относящихся только
  к `serve`.
- Элементы компактной навигации размером 40×40 сохраняют доступные названия;
  узкие панели не создают горизонтальную прокрутку всей страницы.
- После создания или сохранения файла модель, страницы, поиск, диагностика и
  версия рабочего пространства обновляются вместе.
- Обычный HTTP-запрос не запускает сборку. Наблюдатель публикует новую версию
  только после успешной пересборки.
- Мягкий переход не запускает сборку и принимает страницу только с текущей
  версией рабочего пространства. После пересборки портал загружается целиком.
- Поиск и Mermaid не загружаются до первого обращения к ним.
- После мягкого перехода карта экранов, проигрывание сценария и диалог
  дорожной карты инициализируются заново; обработчики предыдущей страницы
  отключаются.
- При конфликте записи текст в форме сохраняется. Ошибка API не мешает читать
  уже открытую дорожную карту.
- Уведомление об обновлении не блокирует содержимое и не появляется снова для
  скрытой версии.
- Конфликт выходного каталога обрабатывается отдельной безопасной веткой.
- `ProjectReport` и HTML строятся из одной проектной модели.
- Бизнес-решение передаётся из модели в presentation layer; DOM не является
  источником permissions или capabilities.
- После UI-миграции browser layers образуют направленный граф `design → ui →
  docs-ui → features → entries`; `design`, `ui` и `docs-ui` не читают product
  runtime через `core`.
- Сгенерированные файлы никогда не становятся источником документации.
