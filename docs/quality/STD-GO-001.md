# STD-GO-001: Качество Go-кода

Стандарт помогает сохранять Toudocu небольшим и предсказуемым. Собранная
программа должна работать без внешней среды выполнения и одинаково вести себя
на поддерживаемых Go-платформах.

<!-- toudocu:section rules -->
## Правила

1. Новая внешняя Go-зависимость допустима только после ADR с объяснением её
   необходимости, закреплённой версией, проверенной лицензией и нужными
   уведомлениями. Чистая Go-зависимость не должна мешать автономной сборке без
   CGO для поддерживаемых платформ.
2. Публичная операция выполняется только явной командой. Запуск без команды не
   должен молча начинать `build`.
3. Новое правило проверки данных сопровождается поведенческим тестом.
4. Исправление безопасности сопровождается тестом, который воспроизводит
   запрещённый случай.
5. Простое исправление без новой нетривиальной логики, кроме нового правила
   проверки данных или исправления безопасности, не требует отдельного
   регрессионного теста.
6. Для простого исправления, которое подтверждает быстрая проверка, не нужен
   сложный долго выполняющийся UI-тест Playwright.
7. Нельзя ослаблять определение корня репозитория и защиту `build --clean`.
8. Обычные `check`, `build`, `serve` и `task context` никогда не выполняют
   команды, записанные в рабочей задаче.

<!-- toudocu:section automated-checks -->
## Автоматические проверки

- `gofmt -w .`;
- `golangci-lint run ./...` со стандартным набором `errcheck`, `govet`,
  `ineffassign`, `staticcheck` и `unused`;
- `go test ./...`;
- `go test -race ./...`;
- `go mod verify`;
- сборка поддерживаемых целей с отключённым CGO.

Эти команды запускает разработчик, рабочая задача или доверенный CI, а не сам
стандарт. Golangci-lint остаётся локальным инструментом качества и не входит в
зависимости или поставляемый бинарник Toudocu.
