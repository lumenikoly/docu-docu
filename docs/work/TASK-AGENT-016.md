# TASK-AGENT-016: Добавить постоянное обсуждение в работу с задачей

<!-- toudocu:section result -->
## Результат

На странице задачи пользователь видит два разных действия:

```text
Спросить
```

отправляет разовый запрос текущему или внешнему агенту;

```text
Обсудить
```

создаёт постоянное обсуждение, которое сохраняет существующий модуль обратной
связи с агентами.

Обсуждение задачи не создаёт отдельную систему комментариев и не повторяет
сущности `Discussion`, `DiscussionMessage` и `AgentDelivery`.

Очередь обратной связи с агентами остаётся единственным способом надёжно
передавать обсуждения агенту-разработчику.

<!-- toudocu:section behavior-change -->

## Изменение поведения

<!-- toudocu:section before -->

### Сейчас

Обсуждение можно создать в общем интерфейсе документации, но в работе с задачей
оно не выделено как отдельное действие.

Поэтому пользователь может спутать разовый запрос «Спросить» в консоли агента с
сохранённой обратной связью, которая должна остаться в истории документа.

<!-- toudocu:section after -->

### После изменения

На панели действий задачи появится отдельная команда:

```text
Обсудить
```

Она открывает существующую форму обсуждения для канонического документа задачи.

После отправки сообщение сохраняется через обычный API обратной связи с
агентами, и для него создаётся обычная доставка `AgentDelivery`.

Далее сообщение может обработать:

* активная консоль агента через `$toudocu feedback`;
* внешний агент-разработчик через существующий навык или рабочий процесс
  командной строки Toudocu.

Очередь сохраняет порядок поступления сообщений.

<!-- toudocu:section scope -->

## Область изменения

* страница задачи;
* `web/src/features/discussions/`;
* представление действий задачи;
* существующие точки подключения интерфейса обратной связи с агентами;
* интеграция с консолью агента;
* локализация, браузерные тесты и документация рабочего процесса.

<!-- toudocu:section out-of-scope -->

## Не входит в задачу

* новая сущность комментариев к задаче;
* отдельная серверная часть обсуждений задач;
* новая очередь;
* передача сообщений в обход `AgentDelivery`;
* отдельные правила порядка обработки для задач;
* автоматический запуск агента после отправки сообщения;
* автоматическое применение запроса на изменение;
* закрытие обсуждения ответом агента;
* перенос содержимого обсуждения в историю сеанса агента.

## Требования к реализации

### 1. Использовать существующую модель предметной области

Для задачи используются существующие сущности:

* `Discussion`;
* `DiscussionMessage`;
* `DocumentAnchor`;
* `AgentDelivery`.

Цель сообщения:

```text
kind=document
path=<канонический документ задачи>
```

Не добавлять `TaskDiscussion`.

### 2. Разделить «Спросить» и «Обсудить»

Интерфейс и документация должны ясно показывать разницу.

#### «Спросить»

* это разовый разговор;
* не создаёт `Discussion`;
* не создаёт `AgentDelivery`;
* ответ остаётся в консоли агента или во внешнем сеансе агента.

#### «Обсудить»

* это сохраняемое сообщение;
* оно попадает в обратную связь с агентами;
* остаётся доступным после завершения сеанса агента;
* создаёт `AgentDelivery` по действующим правилам.

### 3. Форма обсуждения

Команда «Обсудить» на странице задачи открывает существующую форму обсуждения
с уже выбранным документом задачи.

Пользователь выбирает один из существующих видов сообщения:

* `question`;
* `change_request`.

Правила доступа не меняются:

* `question` не разрешает менять файлы;
* `change_request` разрешает менять файлы только в уже заданной области.

### 4. Обсуждение всей задачи и выделенного текста

Действие на панели задачи создаёт обсуждение всего документа задачи.

Если пользователь выделил текст задачи и вызвал существующую команду
обсуждения из контекстного меню, применяются текущие правила привязки к
фрагменту (`DocumentAnchor` и диапазон).

Не создавать для задач второй формат привязки.

### 5. Обработка активным агентом

Если есть активный сеанс агента, интерфейс может предложить:

```text
Обработать с активным агентом
```

Команда передаёт подготовленное обращение `$toudocu feedback` и не вставляет
`DiscussionMessage` прямо в запрос консоли агента.

Навык продолжает использовать существующие команды:

```text
toudocu agent next
toudocu agent respond
```

Поэтому консоль агента не обходит очередь обратной связи.

### 6. Обработка внешним агентом

Для внешнего агента-разработчика нужна копируемая инструкция, которая
направляет его в существующий процесс обработки обратной связи.

Не передавать содержимое обсуждения вручную в новом протоколе передачи задачи.

Внешний агент должен получить сообщение через существующий навык или команды
Toudocu. Это сохраняет:

* порядок поступления сообщений;
* блокировки;
* идемпотентный ответ;
* границы прав доступа.

### 7. Правила очереди

Страница задачи не фильтрует и не меняет порядок очереди обратной связи с
агентами.

Если самое старое ожидающее сообщение относится к другому документу,
`$toudocu feedback` обрабатывает его первым по существующему бизнес-правилу.

Не добавлять обход очереди только для задач.

### 8. Независимость от сеанса агента

Обсуждение существует независимо от жизненного цикла сеанса агента.

Остановка агента, сбой или смена поставщика:

* не удаляют обсуждение;
* не удаляют ожидающую доставку;
* не закрывают обсуждение.

## Критерии приёмки

* [x] `AC-01` На странице задачи есть отдельные действия «Спросить» и
  «Обсудить», и их назначение понятно пользователю.
* [x] `AC-02` Команда «Обсудить» использует существующие `Discussion` и
  `AgentDelivery`, не создавая отдельное хранилище для задач.
* [x] `AC-03` Обсуждение всей задачи использует канонический документ, а
  обсуждение выделенного текста — существующий `DocumentAnchor`.
* [x] `AC-04` `question` и `change_request` сохраняют действующие границы прав
  доступа.
* [x] `AC-05` Команда «Обработать с активным агентом» использует
  `$toudocu feedback` и существующие `agent next/respond`, не передавая
  сообщение напрямую.
* [x] `AC-06` Внешний агент также не обходит очередь и `AgentDelivery`.
* [x] `AC-07` Страница задачи не создаёт отдельную очередь и не меняет общий
  порядок обработки сообщений.
* [x] `AC-08` Обсуждение и ожидающая доставка сохраняются после остановки или
  сбоя сеанса агента.
* [x] `AC-09` После мягкого перехода между страницами в браузере состояние
  обсуждения берётся с сервера, без повторных форм и обработчиков событий.
