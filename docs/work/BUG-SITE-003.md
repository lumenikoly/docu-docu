# BUG-SITE-003: Не блокировать Task Workspace загрузкой действий

<!-- toudocu:section symptom -->
## Симптом

Вкладка «Рабочие задачи» иногда долго загружает элементы и перестаёт отвечать
при переходе к задаче или другой вкладке.

<!-- toudocu:section expected-behavior -->
## Ожидаемое поведение

Task Workspace загружает доступные действия один раз для каждой уникальной
задачи в одном цикле обновления. Чтение действий использует уже построенную
сервером модель портала и не мешает навигации.

<!-- toudocu:section actual-behavior -->
## Фактическое поведение

Каждая копия задачи в доске, списке, дереве и свёрнутых разделах отправляет
отдельный запрос действий. Каждый запрос заново строит полную документационную
модель.

<!-- toudocu:section steps-to-reproduce -->
## Шаги воспроизведения

1. Запустить `toudocu serve` для проекта с несколькими десятками задач.
2. Открыть вкладку «Рабочие задачи» и начать переход к задаче.
3. Увидеть десятки параллельных запросов действий и задержку перехода.

<!-- toudocu:section evidence -->
## Доказательства

До исправления 57 уникальных задач создавали 113 блоков действий и 113
одновременных запросов. Во время этой загрузки переход к задаче не завершился
за 30 секунд. После исправления каждый цикл обновления отправляет по одному
запросу на уникальную задачу, запросы читают готовую модель, а измеренный переход
к задаче занимает 0,22 секунды. Подтверждений прежнего правильного поведения
нет, поэтому ошибка не считается регрессией.

<!-- toudocu:section cause -->
## Причина

Клиент обновляет каждый DOM-блок независимо и не объединяет запросы по
идентификатору задачи. Серверный обработчик чтения действий использует путь,
предназначенный для операций, которым нужна свежая модель перед изменением
исходного файла.

<!-- toudocu:section relationship-to-user-behavior -->
## Связь с пользовательским поведением

Это технический дефект общей рабочей поверхности портала; отдельного
пользовательского сценария для внутренней загрузки действий нет. Дефект мешает
пользователю открыть задачу или перейти на другую вкладку.

- `web/tests/`;

- `internal/app/agent_task_test.go`;
- `internal/site/assets/generated/`;
- `docs/work/BUG-SITE-003.md`.

<!-- toudocu:section out-of-scope -->
## Не входит в исправление

- ленивый рендеринг представлений Task Workspace;
- изменение HTTP-контракта действий;
- изменение правил готовности рабочих задач.

<!-- toudocu:section plan -->
## План

1. Объединить запросы действий по идентификатору задачи.
2. Читать проекцию действий из текущей модели портала.
3. Добавить регрессионные проверки и повторить браузерный замер.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] `AC-01` Task Workspace отправляет не более одного запроса действий для
  каждой уникальной задачи в одном цикле обновления и обновляет все её
  представления.
- [x] `AC-02` Чтение действий не вызывает полное построение документационной
  модели и возвращает состояние и digest из одного текущего снимка портала.
- [x] `AC-03` Переход с Task Workspace остаётся доступным во время начальной
  загрузки действий.

<!-- toudocu:section regression-test -->
## Регрессионный тест

Клиентский тест проверяет объединение одинаковых запросов, а серверный тест —
чтение проекции из модели активного портала без повторного разбора исходной
документации. Доступность перехода подтверждена ручным браузерным замером.

<!-- toudocu:section documentation-impact -->
## Влияние на документацию

Меняется только эта запись об исправлении. Функциональный пользовательский
сценарий и HTTP-контракт Task Workspace остаются прежними; загрузка и переходы
становятся отзывчивее.
