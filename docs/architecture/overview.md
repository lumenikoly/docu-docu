# Архитектура

Toudocu — локальная утилита на Go с небольшим набором закреплённых зависимостей,
скомпилированных в автономный бинарник. Она читает исходные Markdown-файлы,
проверяет связи между ними и собирает статический
HTML-портал. Ту же модель можно получить из Go-кода или через CLI в формате
JSON. Go presentation layer сохраняет полезное семантическое содержимое в
HTML, а интерактивные browser surfaces не получают владение проектной моделью
или маршрутизацией Portal.

Команда `serve` добавляет локальный HTTP-сервер, редактор исходных файлов и
страницу со справкой по внутреннему API. Только основной портал, запущенный
через `serve`, может один раз запросить у GitHub сведения о последнем стабильном
релизе. Для обычной работы Toudocu не нужны база данных, CDN или внешний
сервис.

## Граница системы

Разработчик, CI или программа, использующая Go-пакет, передаёт Toudocu путь к
документации и, когда он нужен, корень репозитория. Утилита читает Markdown,
локальные ресурсы и распознанные OpenAPI-контракты. Затем она либо возвращает
понятный список ошибок, либо создаёт HTML- и JSON-файлы. В loopback `serve`
разработчик может явно открыть Project Terminal: Go-процесс создаёт PTY/ConPTY
и запускает стандартную командную оболочку платформы в корне репозитория.
Последующие команды вводит пользователь. Браузер не задаёт исполняемый файл,
аргументы, рабочий каталог или окружение. Project Terminal и structured Agent Session имеют независимые
жизненные циклы.

Портал после `build` доступен только для чтения. При `serve` браузер может
отправить разрешённое изменение файла, после чего Go-процесс заново читает
документацию и перестраивает портал. Команды проекта запускает только явно
выбранная проверка задачи. Запрос сведений о релизе можно отключить; он не
загружает исполняемый код и отсутствует в статическом и переводном порталах.
