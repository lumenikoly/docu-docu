# ADR-009: Codex app-server как основной транспорт Agent Console

Toudocu использует Codex app-server как основной структурированный транспорт.
Интерактивный PTY остаётся отдельным запасным Terminal Mode.

<!-- toudocu:section context -->
## Контекст

Пользователю нужен один разговор с coding agent внутри `toudocu serve`, где
видны сообщения, состояние ответа, изменения файлов и выполняемые команды.
Запуск второго Codex TUI или разбор его ANSI-экрана создавал бы два процесса и
делал представление зависимым от терминальной разметки.

<!-- toudocu:section decision -->
## Решение

Go-процесс запускает найденный в окружении пользователя Codex напрямую в
режиме app-server и преобразует его protocol events в общий `AgentEvent`.
Браузер работает только с API Toudocu и не знает протокол Codex.

Agent View показывает сообщения и жизненный цикл сессии и ответа. Command
Output является доступной только для чтения проекцией structured command
execution events той же сессии. Он не принимает shell input, сообщения или
решения approval и не запускает второй Codex process.

Если совместимый structured provider недоступен, пользователь может явно
выбрать Terminal Mode. Только этот запасной режим использует PTY и terminal
emulator; его вывод не превращается в structured `AgentEvent`.

Запускаемый файл, аргументы, рабочий каталог и access policy определяет
доверенная реализация и пользовательские настройки Toudocu. Репозиторий и
браузер не могут подменить их. Интеграция доступна только при привязке `serve`
к loopback-адресу.

<!-- toudocu:section consequences -->
## Последствия

- одна Agent Session соответствует одному provider process и одному Codex
  thread;
- Command Output и Agent View коррелируют события, но не становятся источником
  состояния агента;
- static build, translation portal и любой non-loopback `serve` не запускают
  coding agent;
- Toudocu управляет сессией и подготовленными действиями, но не реализует
  собственный agent loop и не вызывает LLM API.
