# ADR-008: React-острова и Vite без превращения Portal в SPA

Toudocu сохраняет многостраничный портал с семантическим HTML от Go. React
19.x обслуживает только прикладные рабочие поверхности и изолированные острова,
Base UI 1.x — сложные составные взаимодействия, а Vite 8.x — сборку ресурсов.

<!-- toudocu:section context -->
## Контекст

Portal должен получить единый долгосрочный фундамент для сложных интерфейсов,
не теряя автономную статическую сборку, вложенные URL и полезное содержимое без
JavaScript. Editor, Changes, Discussions и операция записи Roadmap требуют
состояния, управления фокусом и составных доступных взаимодействий. Перенос
всего Portal в React создал бы второй путь отрисовки документов, клиентскую
маршрутизацию и зависимость обычных страниц от JavaScript.

Browser runtime сочетает framework-free TypeScript с изолированными React
roots и islands, а ресурсы собирает Vite. Решение фиксирует границы этой
действующей архитектуры.

<!-- toudocu:section decision -->
## Решение

Документационная и прикладная модель не содержит HTML, CSS-классов или иной
browser-specific разметки. Go принимает решения о Markdown, связях, Git,
допустимости записи и возможностях страницы. Go presentation code преобразует
подготовленные модели представления в безопасный семантический HTML, JSON и
ответы API. Текущее размещение части этого кода в `internal/app` не определяет
архитектурную границу и не требует рефакторинга пакетов.

Portal остаётся многостраничным сайтом без SPA и React Router. `appearance.ts`,
`portal.ts` и `serve.ts` не импортируют React, React DOM или Base UI.
`screen-map`, `playable-flow` и `api-docs` остаются framework-free.

Разрешены два класса React-поверхностей:

- Editor и Changes являются отдельными page-level application roots. Go
  создаёт оболочку, `PageBootstrap v1`, ресурсы, пустой root и при необходимости
  доступное состояние отказа; React владеет DOM только внутри root. CodeMirror и CodeMirror Merge
  владеют своим чувствительным к задержкам состоянием и не зеркалируют его в
  React;
- stateful features канонического `serve` монтируются только через
  framework-free `IslandHost` и динамический `import()`. Roadmap начинает как
  `eager` island, Discussions — как `activated` island. Новый island не требует
  ADR, пока сохраняет эту границу. Новый класс application root, передача React
  маршрутизации или изменение runtime boundary требуют архитектурного review.

`IslandHost.discover()` идемпотентен. Один island instance имеет не более одного
React root. После полной проверки целевой страницы soft navigation отправляет
`toudocu:pagebeforechange`, вызывает `unmountAll()`, заменяет `.site-layout` и
`PageBootstrap`, синхронизирует ресурсы и только затем отправляет
`toudocu:pagechange` и повторяет discovery. Cleanup освобождает React roots,
effects, listeners, запросы и принадлежащие feature overlays или portals.

Ошибка dynamic import, feature JSON, создания root или первого render затрагивает
только конкретный island. Полезный Go-generated fallback находится вне React
root. Island получает `data-td-island-state="error"` и локализованное сообщение.
Activated island можно повторно запустить новым действием пользователя; eager
island повторяет попытку только после следующего `pagechange`.

Mount point содержит только имя island, instance и при необходимости ссылку на
`application/json` с неизменяемой view model. Runtime, locale, theme,
capabilities, permissions и endpoints поступают только из `PageBootstrap v1`.
Feature JSON не содержит решений безопасности или абсолютных путей и проходит
минимальную feature-specific проверку. React использует `createRoot`, а не SSR
или hydration.

Native HTML остаётся базовым primitive. Base UI применяется, когда встроенного
элемента браузера недостаточно для составного accessibility и interaction
contract: например, для dialog, menu, popover, tooltip, select, combobox или
сложных tabs. Обычные кнопки, ссылки, подписи, layout и статические элементы не
получают обязательную Base UI-обёртку.

Исходники делятся на направленные слои `design`, `ui`, `docs-ui`, `features` и
`entries`. `ui` зависит только от `design`; `docs-ui` — от `ui` и `design`;
features — от нижних слоёв и разрешённой browser infrastructure; entries
компонуют features. `design`, `ui` и `docs-ui` не читают `PageBootstrap`, API,
product events или каталоги через `core`. `docs-ui` получает данные, callbacks
и переводчик через props. Автоматическая проверка импортов защищает этот DAG.

Vite используется только во время разработки и сборки: несколько entrypoints,
dynamic chunks, относительные ссылки, воспроизводимый manifest и раздельные
замыкания `static` и `serve`. Production resources встраиваются в Go-бинарник;
Node.js не является runtime-зависимостью. ADR фиксирует линии React 19.x, Base
UI 1.x и Vite 8.x, а lockfile — точные версии. Major update требует
архитектурного review; новый ADR нужен только при изменении границ решения.

## Рассмотренные варианты

- React для всего Portal и React Router отклонены: они дублируют Go rendering и
  делают документы зависимыми от client runtime.
- Только framework-free TypeScript отклонён для сложных рабочих поверхностей:
  ручное управление состоянием, focus и overlays уже создаёт лишнюю
  реализационную сложность.
- React SSR и hydration отклонены: они добавляют второй rendering pipeline без
  измеримой необходимости.
- Base UI для каждого primitive отклонён: native HTML проще и не связывает всю
  DOM-структуру с библиотекой.
- npm workspaces и отдельные пакеты отклонены до появления самостоятельной
  необходимости в публикации или физической изоляции.

<!-- toudocu:section consequences -->
## Последствия

- Обычная страница Portal сохраняет содержимое без React и работает в корне или
  во вложенном URL.
- Сложные поверхности получают React и Base UI, но не владеют маршрутизацией,
  моделью проекта или решениями безопасности.
- Soft navigation получает явную commit boundary и обязательную очистку islands.
- Go продолжает создавать полезный статический HTML; физическое выделение
  presentation package остаётся отдельным возможным рефакторингом.
- Сборка browser resources усложняется manifest и dynamic chunks, но выпущенный
  бинарник остаётся автономным.
