# Контракт действий задачи

Контракт отделяет смысл действия над задачей от способа передачи инструкции
агенту. Точную HTTP-схему определяет [Task Actions OpenAPI](task-actions.openapi.yaml).

## Проекция и выполнение

`GET /_toudocu/api/tasks/{taskID}/actions` перечитывает каноническую модель и
возвращает текущее состояние задачи, digest, состояние связанной Agent Session,
разрешённые действия и доступные способы доставки. Браузер не вычисляет
разрешения или занятость агента из статуса задачи либо DOM.

`POST /_toudocu/api/tasks/{taskID}/actions/{actionID}` повторяет проверку и
выбирает один из двух способов доставки: `agent-console` либо `handoff`.
Первый использует существующий выбор поставщика в Agent Console. Второй
возвращает готовую переносимую инструкцию и не проверяет наличие поставщика со
структурированным протоколом.

Для действия с фиксированным промтом поле `input.text` может содержать
одноразовое дополнение. Сервер добавляет его к промту только этого POST-запроса
и не сохраняет в задаче, сессии или настройках. Пустое значение запускает
исходный промт без изменений.

Каждый способ доставки в проекции содержит признак доступности. Если Agent
Console занята другой задачей или ручным сеансом без привязки, проекция всё
равно включает `agent-console` с признаком недоступности и серверной причиной
`busy_other_task` либо `busy_unbound_session`; доступный `handoff` остаётся в
списке. Так браузер не восстанавливает ограничение по локальному состоянию и
может показать понятную причину.

Каждый запрос выполнения передаёт `expectedDigest`; сервер отклоняет действие,
если задача изменилась после получения проекции. Только `start-work`
непосредственно меняет статус задачи в Markdown: он также повторно проверяет
готовность и выполняет переход `ready → in-progress`. Остальные действия сами
не меняют этот статус; созданная Agent Session и работа агента могут иметь
собственные последствия.

## Сессия и режим только для чтения

Agent Session всегда связана не более чем с одной задачей. Доставка в сессию
другой задачи отклоняется кодом `busy_other_task`; handoff остаётся доступен.
Ручной запуск из Agent Console не получает неявную привязку к открытой странице.
Пока связанная сессия выполняет turn, останавливается, требует решения или
завершилась с ошибкой, `continue-work` скрыт, а остальные способы доставки в
Agent Console недоступны; индикатор сессии остаётся единственным способом
открыть консоль. В состоянии `idle` `continue-work` отправляет новый turn, а при
отсутствии сессии создаёт новый thread с требованием перечитать актуальный
контекст.

`ask`, `explain-blocker` и `next` используют
`ReadOnlyTurns` при доставке в Agent Console. Handoff просит внешнего агента не
менять файлы и отдельно предупреждает, что Toudocu не может технически
ограничить его разрешения.

`fix-problems` доступно для задач в состояниях `draft` и `needs-attention`.
Оно передаётся обычным turn: агент может исправлять проблемы готовности или
контракта в задаче и репозитории, но не отмечает задачу выполненной автоматически.

Сервер возвращает Markdown вместе с `taskID`, `actionID`, признаком сокращения
и командой получения полного `task context`. Текст ограничен тем же пределом
65 536 байт, что и сообщение Agent Console; сокращение не разрывает UTF-8.
Черновик строится из контракта задачи и проблем готовности, потому что полный
`task context` для него недоступен.

Проекция сообщает отношение активной сессии к задаче, её состояние `off`,
`idle`, `running`, `stopping` или `failed` и наличие ожидающего подтверждения.
Клиент обновляет эти данные после событий Agent Console. Запуск действия не
открывает боковую панель автоматически: пользователь остаётся на странице
задачи и открывает консоль через индикатор активной сессии. При переходе от
неактивного состояния к новой сессии старые сообщения, команды, подтверждения и
вывод очищаются. Из нескольких параллельных ответов проекции применяется только
самый новый запрос для данной задачи.

После типизированной ошибки или конфликта браузер сохраняет введённый текст.
Если буфер обмена недоступен, он показывает handoff в доступном диалоговом окне
с выделяемым текстом и кнопкой повторного копирования, не используя
`window.prompt()`. Успешный переход статуса задачи при этом не откатывается.

## Граница безопасности

Маршруты существуют только в каноническом `serve` на loopback-адресе и требуют
same-origin запрос. Статическая сборка, переводы и non-loopback `serve` не
получают эти endpoints. Browser не передаёт executable, `argv`, рабочий каталог,
окружение, протокол поставщика, политику песочницы или шаблон инструкции.
