# Локальная работа с порталом

Команда `serve` подходит для повседневной работы: она собирает портал, запускает
локальный HTTP-сервер и добавляет редактор, просмотр изменений, обсуждения и
справку по внутреннему API.

## Полный рабочий путь

1. В корне проекта запустите:

   ```bash
   toudocu serve ./docs
   ```

2. Откройте напечатанный адрес. По умолчанию это
   `http://127.0.0.1:8080`.
3. Найдите документ через навигацию или поиск. На странице документа доступны
   действия «Редактировать», «Показать изменения» и «Открыть исходник».
4. В редакторе измените файл и сохраните его. Сервер проверит, что версия файла
   не успела измениться, запишет правку и перестроит модель, HTML и поиск.
5. Если файлы меняет внешний редактор или агент, дождитесь автоматического
   обновления. Несохранённый текст во встроенном редакторе не пропадает: при
   конфликте интерфейс просит выбрать дальнейшее действие.
6. Откройте «Изменения», чтобы проверить текущий Git diff. Обсуждение
   документации можно начать и продолжить там либо прямо на странице документа.
7. При необходимости на странице `roadmap.html` нажмите «Добавить результат»,
   выберите существующий этап, проверьте предложенный `DLV-ROADMAP-NNN` и
   введите одну строку результата.
8. После работы остановите сервер сочетанием `Ctrl+C`.

## Работа с coding agent

В основном `serve` на loopback-адресе откройте Ready задачу и выберите `Start
work` рядом с её статусом. Task Workspace остаётся обзором для поиска и выбора
задачи. При выборе
`agent-console` Agent Console запустит одну Agent Session: Agent View покажет
разговор и состояние ответа, а Command Output — доступный только для чтения
поток структурированных команд. При выборе `handoff` браузер только копирует
готовую серверную инструкцию для внешнего агента. Если доступ к буферу обмена
не сработал, открытое поле позволяет выделить текст вручную или повторить
копирование. Во время ответа в Agent Console можно
направить работу дополнительным сообщением или нажать `Stop response`; `Stop agent`
отдельно завершит всю сессию.

Постоянная правая панель доступна из заголовка на любой странице
основного `serve`. Agent View и Command Output открываются в отдельных
вкладках; на узком экране панель занимает всю ширину под заголовком. Переход или reload
может пересоздать интерфейс, но не остановит server-side Agent Session;
подключившаяся панель восстановит доступный bounded replay и актуальный снимок.
При ширине окна более 760 px перетаскивайте левую границу Console, чтобы
изменить её ширину. При ширине более 960 px так же доступна граница левой
навигации. Обе настройки сохраняются только в вашем браузере; для разделителя
доступны `←`/`→`, `Home` и `End`.

Под полем сообщения выберите модель и уровень reasoning для следующей сессии;
варианты загружаются из установленного Codex и сохраняются для репозитория.
После запуска сессии изменить их нельзя. Там же находится компактный
переключатель полного доступа; обычный доступ остаётся выключенным состоянием.
Setup state показывает provider и проблемы Toudocu skill только когда они
требуют внимания. Install или
update потребуют отдельного подтверждения. `outdated` без compatibility
metadata нельзя использовать дальше, а изменённый, unmanaged, более новый или
unsafe skill получит готовую CLI-инструкцию без автоматической замены. Первое
включение `Full access` также потребует подтверждения для текущего репозитория;
managed и explicit deny policies поставщика при этом не обходятся.

Действия задачи запускают Ask, Clarify, Continue work и `Refresh diff` без
ручного копирования контекста. Для внешнего агента разработки можно скопировать
handoff без запуска Agent Console. Agent Console пока не показывает действие запуска
проверки задачи; ранее полученный вывод проверки остаётся отделён от Command
Output, а отчёт об ошибке передаётся агенту только явным действием. `Process
feedback` отправляет `$toudocu feedback` в активную сессию и сохраняет
существующую FIFO Agent Feedback semantics. Сессия сохранится при переходах между
Tasks, Documentation, Changes и Editor.

На странице задачи «Спросить» означает разовый разговор с агентом.

Терминал проекта открывается отдельно и по кнопке `Запустить терминал` запускает
стандартную командную оболочку платформы в корне репозитория. В ней можно запускать `codex`,
`opencode`, `claude`, Git и другие обычные CLI. Toudocu знает только состояние
PTY и не превращает TUI в Agent Session. Отдельного действия для Codex нет:
его и нужные аргументы пользователь вводит в оболочке самостоятельно. Если не
удалось запустить структурированную интеграцию Codex, Agent Console предлагает
открыть терминал. Agent Session и Project Terminal
могут работать одновременно, а xterm assets загружаются только после открытия
терминала.

Ручная кнопка пересборки полезна, если нужно сразу перечитать документацию. Она
показывает, что именно перестраивается, и не перезагружает страницу до
завершения операции.

## Доступные адреса

- `/` — основной портал;
- `/_toudocu/editor/` — редактор разрешённых исходных файлов;
- `/changes/` — изменения Git и локальные обсуждения;
- `/_toudocu/api-docs/` — справка по HTTP API Editor, Changes и обратной связи
  с агентом;
- `/_toudocu/api/tasks/{taskID}/actions` — доступные действия задачи в основном
  loopback `serve`;
- `/_toudocu/locales/<locale>/` — равноправный locale portal.

Каждый locale portal содержит тот же workspace и пишет только в свой root. Если
отдельной страницы нет, открывается главная страница этой локали.

## Сеть и безопасность

По умолчанию сервер слушает только `127.0.0.1`, то есть доступен с текущего
компьютера. Флаг `--host 0.0.0.0` открывает его для локальной сети. В Toudocu
нет встроенных TLS и авторизации, поэтому такой режим нельзя выставлять в
недоверенную сеть; команда выводит об этом предупреждение.

Agent Console доступен только на loopback. При любой другой
привязке, включая `--host 0.0.0.0`, его endpoints останутся отключены независимо
от настроек пользователя.

Основной портал может проверить наличие новой стабильной версии. Это
единственный необязательный сетевой запрос самого Toudocu в этом режиме. Чтобы
его отключить, добавьте `--no-update-check`.

## Статическая публикация — другой режим

Отдельной команды `preview` нет. Для публикации выполните `toudocu build` и
разместите результат на [статическом HTTP-хостинге](deployment.md). В такой
сборке нет локального API, редактора, просмотра Git и записи в дорожную карту.
