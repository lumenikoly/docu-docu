# Установка навыка Toudocu

Навык `toudocu` уже встроен в исполняемый файл. Команды ниже размещают его для
поддерживаемого агента разработки, показывают состояние, обновляют или удаляют
управляемую копию. Сеть, каталоги расширений, системная оболочка и внешние
менеджеры пакетов не используются.

## Быстрый путь

Из корня проекта выполните:

```bash
toudocu skill install
```

По умолчанию действует `--agent auto`. Если найден один поддерживаемый агент,
CLI выбирает его. При нескольких вариантах интерактивный терминал предлагает
выбор; без интерактивного терминала нужно указать `--agent` явно.

```bash
toudocu skill install --agent codex
toudocu skill status --agent all
toudocu skill update --agent claude-code --scope user
toudocu skill uninstall --agent copilot
```

## Куда устанавливается навык

| Агент | В проект | Для пользователя |
|---|---|---|
| Codex | `.agents/skills/toudocu` | `~/.agents/skills/toudocu` |
| Claude Code | `.claude/skills/toudocu` | `~/.claude/skills/toudocu` |
| Copilot | `.github/skills/toudocu` | `~/.copilot/skills/toudocu` |

Корень проекта выбирается так: явный `--repository-root`, ближайший родитель с
`.git`, текущий каталог. Для области `user` используется домашний каталог
текущего пользователя; `--repository-root` в этом режиме отклоняется.

## Операции

- `install` создаёт отсутствующую копию или обновляет неизменённую устаревшую;
- `status` только показывает путь и состояние;
- `update` требует существующую неизменённую управляемую копию;
- `uninstall` удаляет только неизменённую управляемую копию.

`--agent all` сначала планирует все назначения и убирает повторяющиеся
абсолютные пути, затем обрабатывает каждое независимо. Ошибка одного назначения
не останавливает остальные. Полный успех и ситуация «уже сделано» возвращают
код `0`, конфликт или частичная ошибка — `1`.

## Если найдена конфликтующая копия

`status` различает состояния `not-installed`, `installed`, `outdated`,
`newer-than-bundle`, `modified`, `unmanaged`, `invalid-manifest` и
`unsafe-path`. Изменяющая команда не заменяет неизвестную, изменённую,
повреждённую, более новую или небезопасную копию.

Флага `--force` нет. Сначала сохраните нужные локальные изменения или вручную
переместите конфликтующий каталог, затем повторите команду. Символическая ссылка
`.agents/skills/toudocu`, используемая при разработке самого Toudocu,
считается `unsafe-path` и остаётся нетронутой.

## Как распознаётся управляемая копия

В ней есть `.toudocu-skill.json` версии 1 с версиями навыка и программы, агентом,
областью установки, хешем пакета и SHA-256 каждого файла. Дополнительный,
удалённый или изменённый файл, неверные права и символическая ссылка считаются
локальным изменением. Порядок и пробелы полей самого JSON на состояние не
влияют.

Новый пакет сначала целиком готовится рядом с назначением, манифест записывается
последним. При обновлении и удалении старая копия временно перемещается в
уникальную резервную. Ошибка восстанавливает её. Если восстановление невозможно,
CLI сохраняет резервную копию, печатает точный путь и возвращает
`SKILL_RESTORE_FAILED`.

## После установки

Команды `toudocu skill ...` управляют файлами навыка. Сам процесс вызывается
уже в сообщении агенту:

```text
$toudocu проверь документацию проекта и объясни найденные проблемы
$toudocu подготовь контекст TASK-AREA-001
$toudocu обнови руководство по текущему CLI-контракту
```

Специальные изменяющие процессы также вызываются сообщением и только явно:

```text
$toudocu init
$toudocu refresh
$toudocu refresh diff
$toudocu translate en --from ru --all-stale
$toudocu translate en --from ru --base HEAD
$toudocu clarify миграцию формата конфигурации
$toudocu feedback
```

Различие между командами терминала и сообщениями агенту и границы разрешений
описаны в [руководстве по навыку](agent-workflows.md).
