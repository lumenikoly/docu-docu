# Публикация статического портала

`toudocu build` создаёт каталог только для чтения. После сборки ему не нужны
запущенный Toudocu, Node.js, база данных или CDN.

```bash
toudocu build ./docs --output ./site --clean
```

Загрузите весь каталог `site/` на обычный HTTP(S)-хостинг: например nginx,
GitHub Pages, S3-совместимое хранилище или корпоративный сервер. Одних HTML-
файлов недостаточно: `assets/`, `data/`, `report.json` и локальные ресурсы
проекта входят в результат.

Прямое открытие `index.html` двойным кликом не поддерживается. Для локального
просмотра используйте `toudocu serve` и
[локальный рабочий путь](local-workflow.md).

## Как публикуется этот репозиторий

Собранный портал не хранится в Git. При ручном запуске workflow `deploy site to
pages` GitHub Actions создаёт временный артефакт Pages: сначала русский портал
из основного `docs/`, затем английский из `docs-en/`, затем языковую входную
страницу.

Порядок важен: `project-docs/` очищается и создаётся до
`project-docs/en/`, иначе поздняя очистка удалила бы английскую сборку.

Публичные адреса:

- `/` — выбор языка;
- `/ru/` и `/en/` — русская и английская входные страницы;
- `/project-docs/` — портал из `docs/`;
- `/project-docs/en/` — портал из `docs-en/`.

В корне сначала учитывается язык, который пользователь явно выбрал раньше и
который сохранён в `toudocu-landing-locale`, затем основной язык браузера.
`ru` и `ru-*` ведут на `/ru/`, остальные значения — на `/en/`. На прямом
языковом URL автоматического перенаправления нет. Без JavaScript корневая
страница показывает обе ссылки.

## Размещение во вложенном пути

Ссылки документов и пути к ресурсам относительные, поэтому один выходной
каталог можно разместить как в корне сайта, так и по адресу вроде `/docs/` или
`/projects/my-project/`. Обязательного `baseURL` нет.

Статический результат может стать публичным. Генератор не включает абсолютные
пути файловой системы, настройки локального сервера, данные редактора, учётные
данные и файлы вне разрешённой модели документации.

## Что проверить после публикации

1. Откройте главную страницу и один вложенный документ через HTTP.
2. Убедитесь, что загружаются `portal.css`, `portal.js` и
   `data/search-index.json`.
3. Проверьте поиск, переключение темы и понятное сообщение для неверной Mermaid-
   диаграммы.
4. Повторите те же действия по вложенному URL, если портал публикуется не в
   корне.

Для совместного локального просмотра входной страницы и обоих языковых
порталов в этом репозитории используются `make docs`, затем
`make landing-serve`. Они создают маршруты, совпадающие с Pages.
