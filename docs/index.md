# Toudocu

Toudocu превращает Markdown в репозитории в документацию, которой можно
доверять. Он проверяет ссылки и связи между документами, показывает проект в
удобном портале, помогает разбирать изменения и собирает точный контекст для
рабочих задач и агентов разработки.

Это локальная консольная программа на Go. Исходником остаются обычные файлы в
Git, а для запуска не нужны база данных, npm или отдельная система управления
документацией.

## Какие проблемы решает Toudocu

- **Документация незаметно расходится с проектом.** Ссылки ломаются, дорожная
  карта расходится со статусами связанных пользовательских сценариев, а важные
  связи приходится проверять вручную.
- **Новому участнику трудно увидеть проект целиком.** Архитектура, сценарии,
  решения и текущая работа лежат в разных файлах и не дают единой картины.
- **Агенту разработки передают либо слишком мало, либо весь репозиторий.** В
  результате он заново ищет требования, ограничения и команды проверки.
- **Для публикации Markdown приходится собирать отдельный набор сервисов.**
  Локальный просмотр, поиск, редактор и статический сайт часто живут в разных
  инструментах.

Toudocu не заменяет Markdown собственной базой. Он добавляет к существующим
файлам проверяемую структуру и использует одни и те же данные в CLI, локальном
портале, статической публикации и JSON-отчётах.

## Что вы сможете делать

- **Находить ошибки до публикации.** `toudocu check ./docs` сообщает о битых
  ссылках, повторяющихся идентификаторах, неверных связях и нарушениях
  заявленной структуры, не изменяя файлы.
- **Читать и править документацию в одном месте.** `toudocu serve ./docs`
  открывает локальный портал с поиском, редактором, предварительным просмотром,
  Git-изменениями и обсуждениями.
- **Понимать, что изменилось.** Раздел «Изменения» показывает патч, полный файл,
  вид Markdown до и после правки и различия между известными сущностями
  Toudocu.
- **Связывать работу с её причиной и проверкой.** Рабочая задача хранит
  результат, границы, зависимости, критерии приёмки и команды проверки. В
  портале задачи доступны как доска, список и дерево.
- **Работать с агентом без ручного переноса контекста.** В основном локальном
  портале готовую задачу можно передать установленному Codex или OpenCode.
  Agent Console отдельно показывает разговор и команды, позволяет уточнить или
  остановить работу и продолжает сессию при переходе между страницами.
- **Поддерживать документацию с помощью агента.** Встроенный навык помогает по
  явному запросу создать документацию, сверить её с проектом, обновить только
  затронутые файлы, прояснить решение или перевести выбранную локаль.
- **Публиковать без серверной части.** `toudocu build ./docs` создаёт автономный
  портал для любого обычного HTTP(S)-хостинга. Запущенный Toudocu на сервере не
  нужен.
- **Использовать те же данные в автоматизации.** CLI выдаёт версионированные
  JSON-отчёты, а основные операции доступны напрямую из Go-кода.

Подробный список реализованных функций и ссылки на инструкции находятся в
[каталоге возможностей](reference/features.md).

## С чего начать

Выберите путь по своей задаче:

| Ваша задача | Первый шаг | Результат |
|---|---|---|
| Подключить Toudocu к существующему проекту с помощью агента | Установить [встроенный навык](guides/skill-installation.md) и отправить агенту `$toudocu init` | Минимальная документация, основанная на фактах из репозитория |
| Проверить уже существующий каталог Markdown | `toudocu check ./docs` | Ошибки и предупреждения без изменения исходников |
| Работать с документацией локально | `toudocu serve ./docs` | Портал, редактор, изменения, задачи и обсуждения |
| Опубликовать документацию | `toudocu build ./docs` | Готовый статический сайт и `report.json` |
| Обновить документы после изменения кода | Отправить агенту `$toudocu refresh diff` | Проверка затронутой документации и её зависимостей |

Команды с начальным `$toudocu` — это сообщения агенту с установленным навыком,
а не команды терминала. Полный путь для работы с агентом описан в
[отдельном руководстве](guides/agent-workflows.md).

## Кому подходит Toudocu

Toudocu полезен командам, которые хранят документацию рядом с кодом, хотят
проверять её в CI, публиковать без отдельной серверной платформы или давать
агентам ограниченный и воспроизводимый контекст работы. CLI можно использовать
и без AI-агента.

## Важные границы

- `check` проверяет заявленную структуру и связи, но не подменяет смысловое
  рецензирование текста;
- `task verify --run` выполняет доверенные команды репозитория только после
  явного запуска;
- результат `build` доступен только для чтения;
- редактор доступен только в `serve`, а Agent Console — только в основном
  `serve` на локальном адресе; опубликованный и открытый для сети порталы не
  запускают агента;
- общий прогресс проекта определяется только `roadmap.md`.
