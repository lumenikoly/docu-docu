# Справочник конфигурации

Текущий документационный контракт требует `.toudocu/config.yml` в корне
репозитория. Если файла нет, Toudocu считает проект созданным по контракту v1 и
требует миграцию. Конфигурация разбирается целиком до выполнения команды,
поэтому ошибка общей структуры или ресурса оформления может остановить даже
операцию, которая не обращается к этому полю напрямую.

`build`, `check` и `serve` используют настройки проекта и портала; `changes` и
`task changes` — раздел `changes`; `task init` и `scaffold` — язык проекта.

Корневое поле `documentationVersion` выбирает контракт исходной документации:

```yaml
documentationVersion: 2
```

Текущий контракт имеет версию `2`. Отсутствующее поле означает версию `1` и
требует миграции через Toudocu skill. Значение меньше текущего останавливает
обработку до чтения Markdown с ошибкой `DOCS_MIGRATION_REQUIRED`; значение
больше текущего возвращает `DOCUMENTATION_VERSION_UNSUPPORTED`. Поле должно
быть положительным целым числом. Оно описывает ожидаемый формат, а не результат
последней проверки.

## Значения по умолчанию

| Параметр | Значение |
|---|---|
| Контракт документации | `2`; отсутствие поля означает legacy v1 |
| Каталог документации | `./docs` |
| Выходной каталог | Соседний `project-docs` |
| Корень репозитория | Родитель каталога документации |
| Ссылка репозитория | `main` |
| Срок устаревания | `90` дней |
| Формат CLI | `text` |
| Время одной команды задачи | `10m` |
| Адрес `serve` | `127.0.0.1` |
| Порт `serve` | `8080` |
| Проверка новой версии | Включена; отключается `--no-update-check` |
| Карта экранов | Включена при наличии `screens/SC-*.md` |
| Тема | `classic` |
| Цветовая схема | `system` |
| Акцент | `indigo` |
| Плотность | `comfortable` |
| Ширина текста | `standard` (920 px) |
| Обложка | Включена |

## Оформление портала

```yaml
site:
  title: My Project
  logo: assets/logo.svg
  favicon: assets/favicon.svg
  theme: classic
  colorScheme: system
  accent: indigo
  density: comfortable
  contentWidth: standard
  footer:
    text: My Project documentation
    url: https://example.com
  hero:
    enabled: true
    image: assets/hero.webp
```

Допустимые значения:

- `theme`: `classic`, `paper`, `terminal`;
- `colorScheme`: `light`, `dark`, `system`;
- `accent`: `indigo`, `blue`, `teal`, `green`, `amber`, `rose`, `violet`;
- `density`: `compact`, `comfortable`;
- `contentWidth`: `narrow` (760 px), `standard` (920 px), `wide` (1120 px).

Заголовок выбирается в порядке `--title`, `site.title`, H1 `index.md`, имя
каталога. По умолчанию в подвале название Toudocu ведёт на его входную
страницу. `footer.text` меняет подпись, а `footer.url` добавляет только HTTPS-
ссылку.

Тему и цветовую схему можно переключить в браузере. Выбор хранится локально;
конфигурация остаётся начальным значением для нового посетителя.

Логотип, favicon и изображение обложки должны быть обычными файлами внутри
`.toudocu/assets/`. Абсолютный путь, `..`, символическая ссылка и отсутствующий
файл отклоняются. SVG подключается как отдельный файл и не вставляется в HTML.
Если `site.logo` не задан, в шапке показывается короткая текстовая марка из
итогового названия проекта: первые символы первых двух слов или два первых
символа одного слова. Результат приводится к верхнему регистру. Учитываются
буквы и цифры; если их нет, используется `T`.

Парсер конфигурации поддерживает карты, строки, логические значения и
комментарии. Списки, YAML-якоря и псевдонимы, многострочные значения,
неизвестные и повторяющиеся ключи запрещены. Пользовательских CSS, веб-шрифтов и
плагинов тем нет.

## Корень репозитория

`--repository-root` задаёт:

- границу ссылок из документации на код;
- рабочий каталог `task verify --run`;
- базу для путей из `Область изменения` рабочей задачи.

Укажите настоящий верхний уровень репозитория:

```bash
toudocu check ./docs --repository-root . --strict
```

Если заданы `--repository-url` и точный `--repository-ref`, ссылка на файл за
пределами `docs/`, но внутри репозитория, превращается в HTTP(S)-ссылку GitHub
`blob` или `tree`. Для воспроизводимого портала используйте SHA коммита, а не
плавающую ветку.

## Исключения и устаревание

`--exclude` принимает список через запятую и может повторяться. По умолчанию не
сканируются каталоги VCS, `node_modules`, `vendor`, `dist`, `build`, coverage,
скрытые файлы и символические ссылки.

Дата документа выбирается из `Последнее обновление`, затем `Дата`, затем mtime
файла. `--stale-days 0` отключает предупреждение о возрасте.

Без `--strict` неуспешный код дают только ошибки. С `--strict` его даёт и любое
предупреждение.

## Карта экранов

`--screen-map` включает общую карту, `--no-screen-map` отключает только её
страницу и ссылку. Каталог экранов, страницы `SC-*`, вкладки сценариев, связи и
модель `report.json` сохраняются. Флаги доступны у `build` и `serve` и не
меняют Markdown.

## Изменения Git

```yaml
changes:
  defaultBaseRef: main
  renameSimilarity: 60
  includeTaskArtifacts: true
  includeAssets: true
  semanticDiff: true
  renderedDiff: true
  maxSourceDiffBytes: 2097152
  maxRenderedFileBytes: 1048576
  exclude:
    - docs/generated/**
    - docs/cache/**
```

Раздел необязателен. Без явного диапазона сравнивается
`HEAD → working-tree`. `defaultBaseRef` используется только вместо
отсутствующего `base` и не загружается с удалённого репозитория. Предел размера
отключает тяжёлое представление одного файла, а не весь отчёт.

`--include-assets` временно включает двоичные ресурсы, но сохраняет
`changes.exclude`. `--translation-input` формирует полный читательский набор:
он включает рабочие документы и ресурсы независимо от настроек и произвольных
исключений, оставляя исключёнными только `generated/**` и `cache/**` внутри
каталога документации.

## Локальный сервер

`--host` и `--port` принимаются только у `serve`. По умолчанию сервер доступен
на `127.0.0.1:8080`. `0.0.0.0` открывает его локальной сети без TLS и
авторизации; команда выводит предупреждение.

Браузер сам не открывается, если не указан `--open`. Флагов `--no-open` и
`--edit` нет.

Основной `serve` добавляет редактор, ручную пересборку, Changes и
`/_toudocu/api-docs/`. Всё работает на одном локальном адресе. Статический
`build` не содержит CodeMirror, Swagger UI, адресов API и ресурсов сервера,
хотя копирует найденные OpenAPI-файлы.

При первом запросе основной портал может проверить последний стабильный релиз
и хранит результат до остановки. Полностью автономный запуск:

```bash
toudocu serve --no-update-check ./docs
```

Рабочее пространство включает только обычные `.md`, `.yaml`, `.yml`, `.json`
внутри документации и исключает скрытые пути, настройки `exclude`, выходной
каталог и символические ссылки. JSON-запрос ограничен 3 МиБ, содержимое файла —
2 МиБ. Same-origin защита браузера не заменяет аутентификацию прямого клиента
локальной сети.

## Язык и названия разделов

```yaml
project:
  locale: ru
  sections:
    architecture: Архитектура
    modules: Модули
    use-cases: Пользовательские сценарии
    flows: Процессы
    screens: Экраны
    decisions: Архитектурные решения
    contracts: Контракты
    quality: Стандарты качества
    runbooks: Runbooks
    reference: Справочник
    work: Рабочие задачи
    drafts: Черновики
    guides: Руководства
```

`project.defaultLocale` принимает нормализуемый тег в стиле BCP 47 и обязан
ссылаться на профиль `locales.*`. Каждый профиль задаёт безопасный каталог
внутри репозитория и все 13 встроенных названий разделов. Корни локалей не
могут совпадать, пересекаться или проходить через символическую ссылку.

Локаль активного входного каталога одновременно выбирает встроенный язык интерфейса:
`ru` и региональные варианты `ru-*` включают русский каталог, `en`, любой
другой корректный тег и отсутствие настройки — английский. Это правило едино
для серверного HTML и браузерных состояний. Toudocu не переводит значения
`locales.<locale>.sections`, пользовательское содержимое `site.footer` и содержимое
выбранного каталога документации.

`task init` и `scaffold` без `--lang` используют `ru` или `en` из
активной локали, включая региональные варианты. Для другого
языка берётся `en`; явный `--lang` важнее настройки.

## Локали

```yaml
project:
  defaultLocale: ru
locales:
  ru:
    root: docs
    sections: # полный русский набор
  en:
    root: docs-en
    sections:
      architecture: Architecture
      modules: Modules
      use-cases: Use Cases
      flows: Processes
      screens: Screens
      decisions: Architecture Decisions
      contracts: Contracts
      quality: Quality Standards
      runbooks: Runbooks
      reference: Reference
      work: Work Items
      drafts: Drafts
      guides: Guides
```

Каждый профиль равноправен. `check`, `build`, `find`, `changes`, task workflow,
`scaffold`, `serve`, Editor и Agent Console используют только модель выбранного
root. Операция записи меняет только активную локаль. Toudocu не объединяет
модели и не синхронизирует документы, ID или состояния задач между локалями.

Явный translation workflow задаёт обе стороны: `$toudocu translate
<target-locale> --from <source-locale>`. Подробный процесс — в
[руководстве по AI-skill](../guides/agent-workflows.md#перевести-документацию).

## Mermaid

Пользовательских настроек Mermaid нет. Закреплены:

- `flowchart`, `stateDiagram-v2`, `sequenceDiagram`;
- не более 50 000 байт UTF-8 на блок;
- `securityLevel: strict`;
- запрет front matter и директив;
- цвета, вычисленные из текущей темы.

## Безопасная очистка

`--clean` применяется только к отдельному выходному каталогу. Нельзя очищать
системный корень, исходную документацию, её родителя и путь, который сам
является символической ссылкой. Сравниваются раскрытые реальные пути.

## Отчёт и время команд задачи

`--report <file.json>` атомарно записывает `TaskVerifyReport` вне исходной
документации. `--timeout` ограничивает каждую уникальную команду отдельно, а не
всю проверку задачи целиком.
