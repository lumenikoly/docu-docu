# UC-DOCS-03: Просматривать документацию на локальном сервере

Актор: разработчик.

Разработчик запускает портал на своём компьютере, читает документацию и при
необходимости правит исходные файлы во встроенном редакторе. После сохранения
Toudocu заново читает документы и показывает обновлённый результат.

## Входные данные

- каталог документации проекта;
- каталог, куда будет собран портал;
- адрес и порт сервера;
- необязательный `--no-update-check` для полностью автономного запуска;
- файлы `.md`, `.yaml`, `.yml` и `.json` внутри каталога документации;
- локальный Git-репозиторий, если нужен Changes.

<!-- toudocu:section prerequisites -->
## Предусловия

- Toudocu доступен для запуска;
- разработчик может читать документацию и записывать изменения в документацию
  и выходной каталог.

<!-- toudocu:section main-scenario -->
## Основной сценарий

1. Разработчик запускает `toudocu serve ./docs`.
2. Toudocu читает документацию, собирает портал и выводит адрес
   `http://127.0.0.1:8080`.
3. Разработчик открывает этот адрес, переходит по разделам, пользуется поиском и
   открывает нужный документ.
4. Для правки он нажимает «Редактировать» или открывает
   `/_toudocu/editor/`, выбирает файл и меняет исходный текст. Для Markdown рядом
   доступны предварительный просмотр и сообщения с указанием строки.
5. При сохранении сервер убеждается, что файл не был изменён кем-то ещё,
   безопасно заменяет его и перестраивает модель, HTML и поисковый индекс.
6. Браузер показывает обновлённую страницу. Если файл изменился извне,
   обычная страница обновляется, а редактор с несохранённым текстом сохраняет
   этот текст и сообщает о конфликте.
7. Когда работа закончена, разработчик возвращается в терминал и останавливает
   сервер сочетанием `Ctrl+C`.

## Дополнительные пути

- Раздел «Изменения» показывает локальный Git diff и обсуждения. Полный путь
  описан в [UC-DOCS-05](UC-DOCS-05.md) и
  [UC-AGENT-FEEDBACK-01](UC-AGENT-FEEDBACK-01.md).
- На странице дорожной карты кнопка «Добавить результат» добавляет одну строку
  `DLV-ROADMAP-NNN` в выбранный существующий этап. Перед записью сервер ещё раз
  проверяет, что файл не изменился.
- На `/_toudocu/api-docs/` можно прочитать контракты Editor, Changes и обратной
  связи с агентом. Из этой страницы разрешено выполнять только безопасные
  запросы `GET` и `HEAD`.
- Если в конфигурации объявлены переводы, в шапке появляются переключатели
  локалей. Переводной портал доступен только для чтения; если страницы в нём
  нет, открывается главная страница этой локали.
- Если опубликована более новая стабильная версия, основной локальный портал
  предлагает открыть её страницу релиза. `--no-update-check` полностью
  отключает этот сетевой запрос.
- Принятое расширение основного `serve` позволит Ready задаче запустить Agent
  Console только на loopback-адресе. Целевой путь описан отдельно в
  [UC-AGENT-CONSOLE-01](UC-AGENT-CONSOLE-01.md) и не является текущим поведением
  этого завершённого сценария.

## Ошибочные сценарии

- Если первая сборка не удалась, сервер не запускается.
- Если адрес или порт недоступен, команда завершается с кодом `1`.
- Если проверка версии не ответила, вернула слишком большой или неверный ответ,
  портал продолжает работать без уведомления.
- Если открытый файл уже изменился, сервер возвращает `409 stale_digest`.
  Редактор сохраняет введённый текст и предлагает заново загрузить файл либо
  явно подтвердить перезапись. Повторный конфликт снова требует решения
  пользователя.
- Если дорожная карта изменилась, диалог сохраняет введённые поля, обновляет
  список этапов и просит подтвердить добавление ещё раз. Автоматической
  перезаписи нет.
- Если открытый в редакторе файл удалён извне, введённый текст можно скачать.
- Слишком большой, неверно сформированный, межсайтовый запрос или небезопасный
  путь получает JSON-ошибку и не меняет файл.
- Ошибка повторной сборки показывается в интерфейсе или журнале сервера, но уже
  запущенный HTTP-сервер продолжает отдавать последний успешно собранный портал.
- Если перевод не удалось собрать при старте, его адрес показывает страницу
  `Unavailable`. Поздняя ошибка не заменяет последнюю рабочую версию.
- `--host 0.0.0.0` открывает сервер для локальной сети без TLS и авторизации;
  Toudocu выводит явное предупреждение.

<!-- toudocu:section postconditions -->
## Постусловия

Пока команда работает, портал доступен по HTTP. API редактора читает и меняет
только разрешённые файлы внутри каталога документации. Changes отдельно может
читать допустимые файлы текущего репозитория для diff, полного текста и
обсуждений, но не записывает Git. После `Ctrl+C` сервер и локальные API
перестают работать. Адрес перевода `/_toudocu/locales/<locale>/` доступен
только для чтения: в нём нет редактора, Changes, обсуждений, справки API и
команд рабочего пространства.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] Пока команда работает, портал и разрешённые локальные API доступны по
  HTTP; после `Ctrl+C` они недоступны.
- [x] Editor читает и меняет только разрешённые файлы документации, а Changes
  не записывает Git.
- [x] Адрес перевода доступен только для чтения и не содержит Editor, Changes,
  обсуждений, справки API и команд рабочего пространства.

## Бизнес-правила

Правила определены в документе модуля:

- [BR-SITE-003](../modules/site.md#br-site-003-локальный-сервер-открывает-файлы-только-через-явные-интерфейсы) — Editor ограничен документацией, а Changes читает репозиторий только через проверяемый интерфейс.
- [BR-SITE-007](../modules/site.md#br-site-007-build-и-serve-имеют-разные-возможности) — `build` создаёт статический портал только для чтения, а `serve` добавляет рабочее пространство.
- [BR-SITE-010](../modules/site.md#br-site-010-мягкая-навигация-доступна-только-в-каноническом-serve) — быстрые переходы внутри страницы не меняют поведение статического и переводного порталов.
- [BR-SITE-014](../modules/site.md#br-site-014-дорожная-карта-изменяется-только-ограниченной-операцией) — `serve` умеет только добавить новый `DLV-*`, а Markdown разбирает сервер, не браузер.
- [BR-SITE-015](../modules/site.md#br-site-015-проверка-версии-не-влияет-на-доступность-портала) — ошибка проверки версии не мешает работе портала.

При развитии этого пути отдельно проверяются первая сборка и остановка сервера,

`--no-update-check`.
