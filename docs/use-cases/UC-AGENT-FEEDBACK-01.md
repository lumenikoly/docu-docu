# UC-AGENT-FEEDBACK-01: Обсудить документацию с агентом разработки

Актор: разработчик.

Разработчик задаёт вопрос по документации или изменённому файлу либо просит
проверить и изменить цель, а агент разработки получает запрос через локальную команду и возвращает
ответ в исходное обсуждение.

<!-- toudocu:section prerequisites -->
## Предусловия

- канонический портал запущен через `toudocu serve` внутри Git-репозитория;
- агент разработки имеет установленный навык Toudocu и доступ к командам Toudocu;
- цель находится в канонической документации либо среди обычных файлов
  текущего рабочего Git diff.

<!-- toudocu:section main-scenario -->
## Основной сценарий

1. На странице задачи разработчик может выбрать «Обсудить» для всего
   канонического документа. Действие «Спросить» остаётся отдельным разовым
   разговором с агентом. Для точной привязки разработчик выделяет текст документа, включая заголовок, и открывает
   контекстное меню. Меню позволяет скопировать текст, скопировать контекст или
   добавить сообщение в обсуждение.
2. Разработчик выбирает тип `question` или `change_request`, вводит сообщение и
   сохраняет его. Сохранение атомарно создаёт ожидающую запись очереди, читает
   только целевой документ и локальное состояние и не строит Git-проекцию Changes.
3. Сообщение можно изменить или удалить, пока агент не получил его через
   `agent next`. После получения сообщение неизменяемо.
4. Общая панель обсуждений остаётся на текущей вкладке и показывает все ветки
   проекта, открытые раньше закрытых. Те же ветки видны на каждой странице
   основного Портала и в «Изменениях»; переход между вкладками для ответа,
   редактирования, закрытия или удаления не нужен. Новый вопрос доступен только
   при наличии текущего канонического документа.
5. При активной Agent Session кнопка «Обработать с активным агентом» отправляет
   fail-closed инструкцию в Agent Console. Без активной сессии кнопка
   «Скопировать промт» копирует ту же инструкцию для внешнего агента. Оба пути
   не меняют очередь:

   ```text
   $toudocu feedback
   ```

6. Получив инструкцию, агент разработки до чтения документации, roadmap,
   `UC-*`, `TASK-*`, критериев приёмки или статуса вызывает `toudocu agent next
   --json`. Если команда возвращает `pending=false`, агент останавливается без
   чтения и изменения файлов. Иначе он читает только полученную доставку, её
   цель, историю обсуждения, нужный Git diff и минимальный контекст.
7. Для `question` агент возвращает объяснение без изменения файлов. Для
   `change_request` он изменяет `target.path` и только однозначно названные в
   сообщении дополнительные файлы внутри безопасной границы вида цели. Если
   дополнительный путь неоднозначен, агент возвращает `needs_clarification`.
8. Не запуская команды проверки, агент обязательно передаёт `AgentResponse`
   через `toudocu agent respond` до перехода к следующему запросу или выхода.
   Для `changed` сообщение подтверждает правки и перечисляет `changedPaths`.
   Ответ появляется в исходной ветке, а доставка получает состояние
   `responded`.
9. Разработчик закрывает обсуждение либо отправляет уточнение. Уточнение формирует
   новую запись очереди той же ветки.

## Альтернативные сценарии

- Если очередь пуста, `agent next --json` возвращает `pending=false` и код `0`.
- Открытая ветка без нового сообщения не является ожидающей работой: после
  ответа следующий `agent next` возвращает `pending=false`.
- Если запись уже временно закреплена за обработчиком, второй обработчик получает
  `AGENT_INBOX_BUSY`. После истечения срока закрепления старейшая запись снова доступна.
- Если документ изменился, Toudocu переносит привязку при единственном точном
  совпадении текста либо единственной паре сохранённых контекстов. Иначе
  состояние становится `stale` или `deleted`.
- При состоянии `stale` агент перечитывает актуальный документ. Если намерение нельзя
  определить надёжно, он возвращает `needs_clarification`.
- В едином diff выделение новой стороны создаёт точный диапазон файла. Выделение
  старой стороны создаёт обсуждение файла, а путь,
  старые номера строк и удалённый текст сохраняются как видимая цитата в
  сообщении. Смешанное выделение разрешает только копирование. Полностью
  удалённый файл допускает обсуждение целиком.
- Повторный идентичный ответ не создаёт второе сообщение. Другой ответ для той
  же завершённой записи даёт `AGENT_RESPONSE_CONFLICT`.
- Повреждённое локальное состояние не перезаписывается и возвращает
  `AGENT_STATE_CORRUPTED`.

<!-- toudocu:section postconditions -->
## Постусловия

- разговор и очередь сохранены вне репозитория и переживают перезапуск;
- полученные агентом сообщения и ответы неизменяемы;
- файловая система и обычная пересборка являются источником фактических изменений;
- Toudocu не запускал языковую модель и не менял рабочий код.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] Разговор и очередь сохранены вне репозитория и переживают перезапуск.
- [x] Ожидающие сообщения редактируемы, а полученные агентом сообщения и ответы
  неизменяемы.
- [x] Файловая система и обычная пересборка остаются источником фактических
  изменений.
- [x] Toudocu не запускает языковую модель и не меняет рабочий код.
