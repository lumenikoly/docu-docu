# UC-TASK-01: Получить контекст рабочей задачи

Актор: исполнитель — разработчик или программный агент.

Перед изменением кода или документации исполнитель получает ограниченный
контекст одной готовой рабочей задачи.

## Входные данные

- стабильный ID `TASK-*` либо необходимость выбрать задачу из текущего фронта;
- каталог документации;
- корень репозитория;
- ответ в формате `text` или `json`.

<!-- toudocu:section prerequisites -->
## Предусловия

- Toudocu доступен;
- исполнитель может читать документацию и репозиторий.

<!-- toudocu:section main-scenario -->
## Основной сценарий

1. Если задача ещё не выбрана, исполнитель один раз получает текущий фронт:

   ```bash
   toudocu task candidates ./docs --format json
   ```

   Для выбора внутри одной декомпозиции он добавляет `--parent TASK-ID`.
   Toudocu сообщает единый `workState`, готовность конкретной задачи и
   `descendants` для её ветки. Исполнитель выбирает конкретную исполнимую
   задачу с учётом приоритета и контекста запроса; активные потомки не делают
   родителя автоматически готовым.
2. Исполнитель запускает:

   ```bash
   toudocu task context TASK-ID ./docs --format json
   ```

3. Toudocu находит ровно одну задачу с этим ID.
4. Статус должен быть «Готово к работе», «В работе», «Заблокировано» или
   «Выполнено».
5. В отчёт входят весь контракт задачи, компактные ссылки на родителя, предков
   и непосредственных детей, рекурсивная сводка `descendants`, разделы явно
   связанных документов, заявленное влияние на документацию, бизнес-правила и
   найденные проблемы.
6. `TaskContextReport` версии 1 перечисляет `requiredReads` — файлы, которые
   исполнитель действительно должен прочитать до работы.
7. Исполнитель планирует изменения в рамках цели, ограничений и исключений
   задачи.

Полное содержимое потомков не загружается. Для обзора дерева исполнитель
вызывает `toudocu task tree TASK-ID ./docs`, а для конкретного ребёнка —
отдельный `task context`.

## Ошибочные сценарии

- Отсутствующий ID или несколько задач с одним ID дают код `1`.
- Черновик и отменённая задача не допускаются как контекст реализации.
- Проблемы связанных документов остаются в `issues`, чтобы исполнитель видел
  их до начала работы.
- Ошибка чтения проекта прекращает команду до создания контекста.

<!-- toudocu:section postconditions -->
## Постусловия

Исполнитель получил контекст выбранной задачи. Файлы не изменены, команды из
раздела «Проверка» не выполнены.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] Исполнитель получает контекст ровно одной выбранной задачи.
- [x] До выбора исполнитель может одним вызовом получить готовые задачи и
  подзадачи, а также причины неготовности остальных кандидатов.
- [x] Получение контекста не меняет файлы и не запускает команды из раздела
  «Проверка».
